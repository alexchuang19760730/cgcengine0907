## §4 兩個可複用的發現（比這一次的量測更有價值）

### 4.1 「全程 `thermal=NOMINAL`」在這個 cell 上**做不到**，它不是乾淨窗的可操作定義

即使起跑 NOMINAL、壓縮機安靜，**趟內 HEAVY 採樣仍佔 44–55%**，四趟 worst 全是 HEAVY
（`hist` = N55/M15/H85、N68/M15/H66、N63/M15/H72、N65/M16/H71）。
載入 13.6 GB 模型進 16 GB 盒子跑 decode 本身就會把自己推到 HEAVY。

⇒ 可操作的「乾淨窗」定義應該換成四條，而不是「全程 NOMINAL」：
① 起跑 `thermal=NOMINAL`；② 起跑 `compressor QUIET`；③ 趟內 tg 標準差小（本輪 ≤0.64 vs 髒窗 1.1–1.5）；
④ **過 harness 的 memory gate**（這一條本輪 3/4 沒過）。

### 4.2 16 GB 盒子上，這個 cell 一個場次大概只能連跑 2–4 趟

第 1 趟起跑 swap 4066 MiB ⇒ 第 5 趟起跑 free 只剩 4593 MiB（< 5000 地板）⇒ 拒跑。
每趟 wired 成長約 5.8 GB、swap 峰值成長 570–1446 MiB，**不會在趟間歸還**。
⇒ **8 趟的 ABBA 在單一場次內不可行**，除非先關掉佔用 GB 級的 app 或重開機。
（盒子自己點名：WorkBuddy Helper (Renderer) 2105 MiB、Freebuff 562 MiB、Electron×2 763 MiB。）

⚠ 順帶一提：`scripts/check/memory_pressure.py` 的 mtime 是 **16:18**，
也就是**別條線在我跑的同時正在改這個閘**（`git diff` +494 行）⇒ 閘的絕對門檻（512／5000）
是本輪當下的值，可能會再動。上一輪（15:03）的 log 裡**完全沒有** memory gate 那一節，
因為那時它還沒長成現在這樣 ⇒ **兩輪的放行標準不同，不能直接說「上一輪也 UNUSABLE」**。

## §6 判定

| 項目 | 結果 |
|---|---|
| 起跑乾淨窗（launch NOMINAL ＋ compressor QUIET） | ✅ 四趟都做到 |
| 「全程 NOMINAL」 | ❌ 做不到（趟內 HEAVY 44–55%，見 §4.1） |
| memory gate（臂可用性） | ❌ 區塊 1 3/4 UNUSABLE；區塊 2 起跑前被拒 |
| 配對符號一致 | ✅ 首次一致（+7.11% / +0.70%） |
| 兩對皆 ≥3% | ❌ 只有一對 |
| **判死** | ❌ **未達成** —— 本輪沒有產出可引用的臂比較 |

⇒ **09-26 的 +12.8% 仍然未復現**（本輪 raw +4.7%、對齊後 +2.5~3.3%，都不到一半）。
⇒ 但「完全沒效應」也**沒有**被證成：本輪是第一次兩對同號。
⇒ 真正的結論是：**這顆 cell 在目前這個盒子狀態下量不出判死所需的證據**。

## §7 處置

1. **維持不改 `scripts/run_server.sh` 的預設值**（`CGC_CB_N_MAIN` 維持 unset）。
2. **本輪的 t/s 不進任何結論**（3/4 UNUSABLE）；§5 的對齊值只當提示。
3. 要判死，先讓盒子安靜（關掉 GB 級 app 或重開機），再一次跑滿 8 趟
   （區塊 1 ABBA ＋ 區塊 2 BAAB，兩個區塊都過 memory gate）。
   ⚠ 依 §4.2，**兩個區塊中間要讓盒子回到 free ≥ 5000 MiB**，否則第二區塊會被拒跑。
4. 若仍無法拿到 ⇒ 依 `on_fail` 登記為「**本盒子無法判死**」，不是「效應為零」。
