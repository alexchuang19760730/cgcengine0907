# L25-2 機制指名（2026-09-30）：`sg-kernel-busy` ＋ skip-probe

**這一格要的是什麼**（看板 L25-2）：在四塊的**已量上界**相加仍 > 40.0 ms 的情況下，**指名一格 ＋ 它上界
以外的機制**（⛔ 不得再指 B 半補丁）。`accept`＝該格出現超出上界的實測（且 M1 過）；`falsify`＝指不出來
⇒ 25 維持判死。

## 0. 起點（§39 §二／`docs/NEXT_ACTIONS_2026-09-29.md`）

以各塊**已量上界**代入：`19.5（kernel）＋ 12.0（gap）＋ 5.8（圖外）＋ 3.9（填充提交）＝ 41.2 ms ＝ 24.3 t/s`
＞ **40.0 ms**（25 t/s）⇒ 以 ms 為軸的拆解**不成立**；要成立，**至少有一格得超過自己的上界**。

## 2. 剩下的那條：`sg-kernel-busy`（唯一「一次 build ＝ 一個答案」）

- **它缺的東西**：不是旋鈕、不是儀器，是**承載算子**（§40 表格）。
- **指名的機制**：把**群集 1** 的 117 個完全未融合的以小為單位的 dispatch
  （`ffn_moe_weights_sum`[1] → `_clamped`[1] → `_norm`[8]；8.6% 的 dispatch 數）**換成一顆承載算子**
  ≈ `ffn_moe_weighted`（§18 §七）。
- **為什麼它能「超過上界」**：它動的是 `kernel 19.5 ms` 這一塊本身，而這一塊的**未開採上界**
  已被量出來：**群集 1 的 7.4 ms**（§18 §一二；份額價 1.89 ms）。
  41.2 − 7.4 ＝ **33.8 ms ⇒ 29.6 t/s**，而赤字只有 **1.2 ms** ⇒ 上界**足夠**蓋過赤字。
- **第一趟（跑前寫死）**：§18 §七(4) 的 **skip-probe** —— env-gated（預設關）、跳過所有輸出
  **元素數 ≤ 8** 的 dispatch（`SUM_ROWS`[1]／`CLAMP`[1]／`DIV`[8]／scalar sigmoid）。
  ⚠ 這一臂的輸出**必然是錯的（VOID）**，它只把「7.4 ms 的上界」換成**實測 Δstep**；
  這是本 repo 已有的模式（`CGC-HOOK=0`、「權重不進池」都是靠故意錯的臂量上界）。
  - 判別句：**Δstep ≥ 1.2 ms**（＝赤字）⇒ 值得寫那顆承載算子；**Δstep < 1.2 ms** ⇒
    群集 1 不是槓桿，`sg-kernel-busy` 與 L25-2 一起**判死（附機制）**。
- ⛔ 明確禁止（§40）：在 skip-probe 前就寫那顆 ~300 行的融合 kernel；用 63 µs/dispatch 的外推當單價。
- ⚠ **不要把期望讀成「有 35 ms 可撿」**（§40 2026-09-29 追加更正）：天花板就是 7.4 ms，
  而且 kernel 這一塊的**主目標（19.5）所依賴的機制已被量成反方向**（§17 §三：一層 8 專家一次 dispatch
  **已經是現況**；`CGC_MMV_FUSE=1` 再併一次 ⇒ dispatch −9% 而每步 **+3.5%**）。
