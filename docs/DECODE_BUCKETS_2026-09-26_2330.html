① 目標函數與判準（operator 權威表述）

「把除 compute time 以外的時間（gap／wait／cb／fill）最大程度地消除，同時 M1/M2/M3 保持 bit-identical。」M1/M2/M3 是護欄不是獎勵。

wait — CPU 自旋等該段完成 cb — expert cache 填池 IO（不是 command buffer） submit — 下一段的提交 gap — 段與段之間的 GPU 空窗 fill — ensure_batch 阻塞填池

★ 判準是「控制臂漂移」，不是固定門檻。 兩個同 build、同配置的off臂（頭尾各一）之差就是本次的噪聲底；任何 Δ 沒有超過它就不能宣稱是訊號。本次實測噪聲底：wait ±7.0%／union ±10.6%／gap ±6.5%／busy ±19.2%／tg ±11.3%。

② 三支儀器與一個可信度閘

全程開 CGC_DECODE_PROFILE=1;CGC_HOOK_SPLIT=1;CGC_GPU_TIMING=1。GPU_TIMING 零擾動 —— 只讀 Metal 自己記的 GPUStartTime/GPUEndTime，不插 barrier。

儀器欄位語意來源
CGC-GPUTIMEunion / gap / busy / skippedbuffer 的 GPU 執行聯集／段間空窗／各 buffer 時長之和ggml-backend.cpp:2141-2172
CGC-DECPROF（ntok=1）total / wait / cb / submit步總時間（= tpot）與 CPU 三桶同檔 :3024-3050
CGC-HOOKSPLITpre / ensure / drain / tailensure = 阻塞填池 ⇒ 就是 fillllama-context.cpp:7746-7761

★ skipped% 要做「整臂」閘，不是逐行閘。 儀器自帶 skipped=，說明書要求它為 0 —— 但必要不充分：n_main=128 那次連 skipped==0 的行都報 busy=2872 ms／wait=94.7 ms（3034%，物理不可能）。⇒ 門檻 20%，超過則該臂的 union/gap/busy 整臂不可讀；而 tpot/cb/submit/fill 仍有效（它們來自 DECPROF／HOOKSPLIT，不依賴 Metal 時間戳）。
機制（ggml-metal-context.m:1140-1175）：n_main 變大 ⇒ n_nodes_1 變小 ⇒ 平行執行緒分不到節點 ⇒ 空 command buffer ⇒ 無時間戳。這解釋了為何 n_main=16/32（比預設 64 小）幾乎 0%，而 128 是 68%。

⚠ fill 的口徑陷阱：HOOKSPLIT 的 n 是累計調用數、四欄都是累計平均、每 160 次打一行 ⇒ 取最後兩個窗口的增量才是穩態；直接讀最後一行會被 prefill 拉高。

④ ★ 新發現：busy/union 比 1.49 → 1.00

busy = Σ 每個 buffer 的 (GPUEnd−GPUStart)；union = 這些 buffer 的聯集 span。兩者之比量的是「同一步內 GPU 上的並行重疊程度」。

off（n_main=64）busy 108.27 / union 72.44
union 72.44
重疊 +49%
on（n_main=32）busy 55.90 / union 56.09
union 56.09 · 重疊 ≈ 0

⇒ n_main 不只改「誰來編碼」，它改變了 GPU 端的並行結構。 這解釋了為何 busy 掉 48% 而 union 只掉 23% —— 中間那 25 個百分點就是被消掉的重疊本身。

⚠ 但這對目標函數是壞消息：union 少掉的約 16 ms 並沒有變成 tg 的收益（④ 的 +9.4% 未過檻）⇒ n_main=32 是用「段內並行」換「段間空窗」，總時間守恆。

⑤ 環境與方法（本輪最貴的三個教訓）

教訓現象處置
「無 llama 進程」≠ 空窗14:58 單次窗口門通過，卻正好落在另一個 session（/tmp/armed_fc.sh，paired MTP）兩臂之間的間隙 ⇒ 擠進別人實驗中段，thermal 1→2改成連續 3 次（間隔 20s）都乾淨，且乾淨的定義含 thermal == NOMINAL（別人跑 GPU 一定發熱，這是不需要知道對方腳本名的第三方信號）
16 GB 上不能一支腳本跑四臂每臂 swap +8~9 GB，第 3~4 臂必 OOM（min_free 14.09／14.14 MiB，是 macOS 硬底）拆成相鄰一對 × 2 段；run_pair.sh 在每臂起跑前等 swap 回落（門檻 6000、上限 600s）
swap 會自然回落（與 purge 無關）off1 結束時 11562 MiB，6 分鐘後 3188 MiB —— 引擎退出後 macOS 回收它的匿名頁這糾正了我第一版「看到高就停手」的錯誤閘。⚠ purge 對此無效（它不減 swap_used，實測 free 0.07→7.3 GB 而 swap 6490–6770 不動）

可複製：Backup/phase_decomp/cbnmain_pair/run_pair.sh（相鄰一對 ＋ 臂間等 swap 回落）、cbnmain_nm32/gate.py（fail-closed thermal）、cbnmain_nm32/analyze.py（完整拆解表，支援 ctl*/nm* 與 off*/on* 兩種臂名）。
