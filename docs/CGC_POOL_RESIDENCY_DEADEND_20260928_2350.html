結論先講

(B) 那條路（pool 改 file-backed）不存在 —— CGC_MMAP_POOL_FIX 不是開關，是 shell 探測變數。替代它的 soft pool 路，實測 常住足跡完全沒降（wired 12402 MB vs 控制 12364 MB，+0.3%，噪聲內）。 加上既有的「縮 pool」真曲線，三條記憶體側的路全部封死。

1. 先更正：CGC_MMAP_POOL_FIX 到底是什麼

上一輪建議「用 strings 確認它在不在，在就開一趟對照」。查完的結果是我的前提錯了：

我以為其實
它是 CGC_* env 儀器，strings 找得到 在任何 dylib／執行檔裡都是 0 命中 —— 它是 run_server.sh:1024 的 shell 變數
找到就能當開關開 A/B 它是探測變數，由 strings -a libggml-metal*.dylib | grep -c '_Pool' 算出（:1027）
它跟 pool 換頁行為有關 它只服務 load_mode=mmap 那條路（:1146-1158），判「binary 有沒有 _Pool buft 修復」

可檢查的事實

strings -a libggml-metal.0.dylib | grep -c '_Pool' ⇒ 1（修復存在）。

但 run_server.sh:1140-1142 白紙黑字：「只在 use_mmap 時選它，所以 load_mode=none 路徑的 buft 選擇與以前逐位元相同。」 交付 cell 就是 load_mode=none ⇒ 這條路在我們的 cell 上是 no-op。

而且它早已被量過、被判「不是槓桿」（run_server.sh:1089 原文）

「mmap（不是槓桿，不要再試）：……修好之後它在 4096/5120/6144 全部不存活（0/3）， 而且工作集警告只在 mmap 出現 ⇒ 它把 GPU 工作集撐大。」

⇒ 不需要、也不應該為它開一趟。上一輪的建議作廢。

2. 替代路：soft pool 降可駐留槽位（本輪實測）

2.1 為什麼值得問

上一輪算出：wired 峰值 12.4 GB（模型權重 Metal 駐留）＋ pool 8 GiB ＝ 20.4 GiB vs 實體 16 GiB ⇒ 必有 ~4.4 GiB pool 頁在 swap 上。那輪說「縮 pool 不行」（真曲線 8G 12.06 → 6G 10.48 → 4G 7.67 t/s）。

但 soft pool 是另一件事：pool 仍配置 8 GiB、n_slots 仍 143， 只是槽位 64..142 標為 spare「currently unused」⇒ 若那些頁真的永不觸及，常住足跡應從 8 GiB 降到 ~3.6 GiB，而不改變 pool 的宣告容量。這是第一個「砍掉那 4.4 GiB 卻不縮 pool」的候選。

2.2 旋鈕真的生效（見證行）

CGC Soft Pool init: L0=32 L1=32 (n_slots=143, partition active)
pool_cap_slots=143

對照：交付 cell 當前被 run_server.sh:2294-2302 強制設為 0/0， 印 L0=0 L1=0 (partition disabled) ⇒ 本趟確實是「開著」的那一面，不是靜默 no-op。

三條獨立的記憶體指標，沒有一條支持假設

  • max_wired 12402 MB vs 控制 12349–12423 ⇒ 差異 +0.3%，在噪聲內 ⇒ 常住足跡一點都沒降。spare 槽位仍然被觸及（與 prewarm_hot 會填滿 143 槽一致）。
  • pageins 增量 1,774,912 ⇒ 比所有控制都高（off_a 1.62M，+9.5%），方向相反。
  • swap 成長 +4846 MiB 是四趟最大。

⇒ 假設「spare 槽位永不觸及 ⇒ 常住足跡降 4.4 GiB」被證偽。

2.4 速度面：UNDECIDED，但已無意義

  • 預註冊 falsify 門檻 tg ≤ 9.0：中位 9.13、rep1 10.17 ⇒ 都沒過門檻 ⇒ 字面上 UNDECIDED。
  • 按 §1.18 規則看 rep1 不看中位：rep1 10.17 vs 控制 10.87／10.74 ⇒ −5.5%／−6.4%，落在 MDD 8.5% 內 ⇒ 速度差不可判。
  • 中位 −16% 那部分是 carry-over 簽名（reps 單調遞減 10.17 → 9.13 → 8.38）。

關鍵：不管速度面判不判得出來，記憶體面已經證偽 ⇒ soft pool 沒有 upside 去平衡任何速度代價 ⇒ 沒有理由再投入。

2.5 hit% 不變（96.2% = 控制）

soft pool 被關掉的原始理由（run_server.sh:2288-2293）是命中率層面： 「placement 最多值 0.2pp（current 90.3% vs best-possible 90.5%）」。本趟實測 hit% 96.2%，與 off_a／off_b 完全相同 ⇒ 那個理由在本 cell 上再次成立 ⇒ soft pool 既不省記憶體、也不改命中率。
