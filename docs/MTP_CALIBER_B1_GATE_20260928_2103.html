MTP 口徑重定義 B1：把「輸出函數不同」寫進推廣閘門

2026-09-28 21:03 · 本線（線A · ace）· 0 build · 立項卡 docs/MTP_CALIBER_REDEFINE_CHARTER_2026-09-28.md · 落地點 scripts/check/mtp_promotion_gate.py、scripts/check/mtp_off_baseline.json
一句話：既有推廣閘門的 8 條規則判的是盒況可比性；本輪補上獨立的一層 「輸出函數是否同一個」。結果是：一個配對全綠、ON 快 +21.4% 的候選， 閘門仍給 ELIGIBLE，但機器會明確印出 NOT INTERPRETABLE AS A SPEEDUP —— 「X% of off」這種寫法從此有欄位可擋，不再只靠人記得。

1. 補的是哪一個洞

立項卡 §1 已證：MTP on 讓 cparams.n_rs_seq 從 0 變成 draft.n_max > 0（src/llama.cpp/common/common.h:395 need_n_rs_seq()），於是 src/llama.cpp/src/models/delta-net-base.cpp:494 的 if (cparams.n_rs_seq == 0) 改走「K 槽位回滾」而不是「單槽位原地寫回」—— 計算份數本身變了（gdn 30→60、conv_input 30→150）， 第一個 decode 就分歧（pos=209：off 19.22745 vs on 19.25835）。

既有閘門完全沒碰到這一層。它問的是「這兩個讀數是不是在同一個盒況窗口裡量出來的」， 而沒問「這兩個讀數算的是不是同一個東西」。缺口的後果不是抽象的——下面的 demo 是具體的。

1.1 一個「ON 快 21.4% 且配對全綠」的候選

Backup/b1_gate_demo/cand_on_faster.json：off 11.61 vs on 14.09 t/s， null 底噪 0.18%，兩側 spread 0.26%／0.43%，cell 15 維全等，design: ABBA。 這是既有 8 條規則全部通過的情形：

verdict: ELIGIBLE
  output function: candidate=MTP-on baseline=MTP-off identical=False
  NOT INTERPRETABLE AS A SPEEDUP: on t/s only as 'MTP-on output function'; never as a % of off
    root cause: cparams.n_rs_seq 0 -> draft.n_max > 0 (delta-net-base.cpp:494)
  note: paired ratio: on/off = 1.214x (14.10 vs 11.61 t/s)

改動前，這份輸出只會有最後那行 ratio，讀者拿到的是「MTP 加速 21.4%」。 改動後，ELIGIBLE 仍然給（正確——配對確實可比），但語義被機器標住了。

2. 新增的機檢欄位

欄位意義
output_function.identical 兩側是否同一輸出函數。由 spec 歸一化；candidate 可用 output_function 顯式宣告，優先於 spec
output_function.root_cause 不同時給出源頭（n_rs_seq 0 → >0 與檔案行號），不讓人自行猜
comparability.paired_comparable 既有 8 條（盒況可比性），語義不變
comparability.interpretable_speedup paired_comparable AND identical —— 只有兩者都成立，才可寫「X% of off」
comparability.claim_rule 人讀的一句話，直接印在主輸出裡

歸一化規則（fail-closed）

  • "" / none / off / "none (MTP off)" → MTP-off
  • 含 mtp / draft / spec → MTP-on
  • 未知的非空 spec → 原字串回傳，永遠不等於 MTP-off ⇒ 判為不同函數。 寧可誤擋一個新 spec 名，也不要默認「應該是同一個函數」。

⚠ M1 第一次沒紅 —— 一條值得記的教訓

第一版只斷言布林值 identical。結果 M1（清空 marker 表）沒有讓自測變紅， 因為 fallback 本身也 fail-closed：未知 spec 回傳原字串，同樣不等於 MTP-off， 兩條路徑結果相同 —— 這在突變測試裡叫等價突變，不是程式對，是斷言沒有區分力。

修正：改為同時斷言歸一化後的字面標籤（MTP-on／MTP-off／原字串）。 改完 M1 立刻變紅。

通則：斷言要能區分「對」與「碰巧對」。只斷言布林結果的測試， 在有多條路徑通向同一結論時是假的安全網。

5. 卡上的一條錯誤認知已修正

$ python3 agent_harness/engine_loop/index_assets.py --check | grep mtp_

    scripts/check/mtp_promotion_gate.py:  on disk but not in the manifest

6. 適用範圍與未做的事

B1 現在擋的是「表述」，不是「比較」。

  • 配對比較本身仍然合法、仍然要繼續做 —— ON 到底比 OFF 快或慢，是實證問題。
  • 擋掉的是：把 ON 的 t/s 寫成「OFF 的 X%」。這在兩個輸出函數之間是未定義的， 不是「雜訊大一點」。
  • 因此 verdict 與 exit code 都沒有改：既有 8 條的語義完整保留。

未做

  • 索引未重生 —— 理由見 §5（別條線 76 筆 WIP）。
  • B2 第二批那 7 份未追蹤檔已加標籤但仍未 stage（屬別條線未提交檔案，不併入本線 commit）。
  • 本輪沒有任何量測：沒 launch、沒 GPU 取樣、沒產生新的 t/s 讀數。 demo 候選的數字是構造來驗證閘門語義的，不可當成效應量級引用。
