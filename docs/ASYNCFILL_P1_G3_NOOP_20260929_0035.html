一句話：開卡時把 P1 寫成「待做」，查證後發現 G3 早就落地 （CGC_ZERO_SLOT=1），但它在 prod-new 交付路徑上一次都沒運行 —— 不是「沒有 miss」，是 writer 壓根沒進迴圈。

1. 兩點更正

(1) 已落地：不必動線 I 的檔

  • 專用旋鈕 CGC_ZERO_SLOT=1 已於 09-26 進 scripts/run_server.sh allowlist（:1752-1753）。
  • zero_slot_enabled()（llama-expert-cache.cpp:311-313）已含它 ⇒ gate 早已放寬，推翻開卡時「gate 要放寬」的記載。
  • binary 已含：strings -a libllama.0.dylib | grep -c CGC-G3-ZEROSLOT = 2（build 630）⇒ 0 build 即可跑。

(2) 開卡時引用的行號是錯的（勿再引用）

  • llama-expert-cache.cpp:277-282 是驅逐邏輯；:292-316 是 zero-slot 的 MTP fast path。
  • llama-graph.cpp:2718 是 gelu。
  • CGC_ZERO_MISS 在 src/ 裡 0 命中（該 env 不存在）。
  • 真正的點在 llama-context.cpp:3745-3815（B-scheme slot table writer）。

2. 實測

⇒ 不是「沒有 miss」，是 writer 根本沒運行。

3. 原因（源碼級）

  • cache_slot_table_tensors 只在 DECODE graph 由 build_moe_ffn 填（llama-context.cpp:3448-3450）。
  • slot table leaf 是 if/else ⇒ 預設不建（llama-graph.cpp:2491 原話 "the leaf is NOT built when the table is"）⇒ prod-new 交付臂沒有這個 leaf ⇒ map 為空 ⇒ 每一層都被 continue 掉。

4. P1 原本的 exit 寫錯了

源碼註釋（llama-context.cpp:3768-3772）原話： "That is NOT bit-identical to the segmented arm, and it is not meant to be"。

G3 是故意不 bit-identical：把 unbounded／arbitrary error（指向別人的權重）換成 bounded／deterministic／interpretable 的 0。原 exit 要求 M1 9/9 是 原理上不可能達成的門檻（原文另寫 "A zero slot does NOT make G1 pass"）。

⇒ 已改為見證行判據：zero_slot>=0 且 placeholder==0。
